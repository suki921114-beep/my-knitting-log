# 프로덕션 출시 체크리스트

versionName `1.8.1` / versionCode `34`
공개 테스트는 건너뛰고 프로덕션으로 갑니다.

---

## ⚠️ 단계적 출시를 꼭 쓰세요

프로덕션 트랙에서 버전을 만들 때 **출시 비율**을 정할 수 있습니다.

```
5% 로 시작 → 이틀 관찰 → 20% → 50% → 100%
```

문제가 나오면 그 지점에서 **출시 중단**을 누르면 됩니다.
100% 로 한 번에 열면 되돌릴 방법이 없고, 이미 받은 사람에게서 앱을 회수할 수도 없습니다.

지금 테스터가 열 명 남짓입니다. 넓은 기기에서 어떻게 도는지 아직 모르니
천천히 여는 편이 낫습니다.

---

## 1. 앱 콘텐츠 (정책 → 앱 콘텐츠)

프로덕션은 심사가 더 깐깐합니다. 하나라도 비면 출시가 막힙니다.

- [ ] **데이터 보안** — `data-safety.md` 보고 그대로 채우기
- [ ] 개인정보처리방침 URL — 웹 배포 주소 + `/privacy`
- [ ] 광고 포함 여부 → **아니요**
- [ ] 앱 액세스 권한 → 로그인 없이 전체 이용 가능하다고 적기
      (클라우드 백업만 로그인이 필요한데, 그건 지금 명단 계정만 쓰므로
       심사자가 볼 수 있는 기능이 아닙니다. 이 사실을 메모에 적어두세요)
- [ ] 콘텐츠 등급 설문
- [ ] 타겟층 → 13세 이상, 아동 대상 아님
- [ ] 정부 앱 아님 / 금융 앱 아님

---

## 2. 스토어 등록정보

- [ ] 앱 이름 · 간단한 설명 (80자) · 자세한 설명
- [ ] 앱 아이콘 512×512
- [ ] **피처 그래픽 1024×500** ← 없으면 출시 불가
- [ ] 휴대전화 스크린샷 **최소 2장** (권장 4~8장)
- [ ] 7인치 태블릿 스크린샷
- [ ] 10인치 태블릿 스크린샷

### 스크린샷에 넣으면 좋을 화면

1. 홈 — 진행중 프로젝트와 단수 카운터
2. **도안 보며 뜨기** — 화면이 갈라진 모습 (이번 업데이트의 얼굴)
3. 도안 PDF 뷰어
4. 실 라이브러리 — 잔여량 막대가 보이는 목록
5. 프로젝트 상세
6. 다이어리
7. 백업 화면

`05-backup.jpg` 가 아직 없습니다.

## 3. 프로덕션 버전 만들기

- [ ] 테스트 및 출시 → **프로덕션** → 새 버전 만들기
- [ ] AAB 업로드 (versionCode 34)
- [ ] 출시 노트 — `release-notes.md` 참고
      ⚠️ 프로덕션 첫 출시는 "새로운 기능" 이 아니라 **앱 소개**에 가깝게 쓰는 게 낫습니다.
      처음 보는 사람에게 "뒤로가기를 고쳤어요" 는 아무 의미가 없습니다.
- [ ] 국가/지역 — 대한민국
- [ ] **출시 비율 5%**

## 4. 프로덕션 첫 출시 노트 (제안)

```
뜨개하면서 남기는 기록장이에요.

· 프로젝트별로 단수를 세고 사진을 남겨요
· 도안 PDF를 넣어두고 앱에서 바로 볼 수 있어요
· 도안을 보면서 단수를 셀 수 있어요 — 화면이 위아래로 갈라집니다
· 가진 실의 잔여량이 자동으로 계산돼요
· 실·도안·바늘·부자재를 한곳에 모아둬요
· 게이지로 실과 도안을 찾을 수 있어요

로그인 없이 바로 쓸 수 있어요.
```

## 마음에 걸리는 것 두 가지

**클라우드 백업이 "준비 중" 으로 보입니다.**
프로덕션 사용자가 보면 미완성 앱으로 느낄 수 있습니다.
아예 안 보이게 감추거나, 문구를 "곧 만나요" 처럼 다듬는 쪽을 생각해 보세요.

**도안 PDF가 기기에만 저장됩니다.**
안내 문구는 있지만, 일반 사용자는 앱을 지웠다 깔고 나서야 알게 됩니다.
파일 백업을 지금보다 눈에 띄게 두는 게 안전합니다.
