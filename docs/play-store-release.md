앱 이름: **뜨개일기** / 패키지: `com.suki.knittinglog`

전체 과정은 처음이면 하루~이틀, 이후 업데이트는 30분 정도 걸립니다.
심사는 보통 며칠, 첫 출시는 최대 2주까지 걸릴 수 있습니다.

## 1. 개발자 계정 만들기

1. <https://play.google.com/console> 접속
2. **개발자 계정 만들기** → 개인 / 조직 선택
3. 개발자 이름 입력 — **스토어에 공개되는 이름**입니다 (예: 쿠쿠다스)
4. $25 결제
5. 신원 확인 서류 제출 → 승인까지 보통 1~3일

승인 전에도 앱 등록은 시작할 수 있지만, 출시는 승인 후에 가능합니다.

## 2. 서명 키(keystore) 만들기 — 가장 중요

> **이 파일을 잃어버리면 앱을 영원히 업데이트할 수 없습니다.**
> 구글도 복구해 주지 않습니다. 앱을 새로 올려야 하고 기존 사용자는 따라오지 못합니다.

Android Studio 에서:

1. **Build → Generate Signed App Bundle / APK**
2. **Android App Bundle** 선택 → Next
3. **Create new…** 클릭
4. 입력값:
   - Key store path: `C:\Users\ddoro\keys\ddegae-release.jks` (프로젝트 폴더 **바깥**에)
   - Password: 강한 비밀번호
   - Alias: `ddegae`
   - Validity: 25 년 이상
   - 이름·조직 등은 대충 적어도 무방
5. OK

### 만든 직후 반드시

- `.jks` 파일을 **클라우드 드라이브 등 두 곳 이상**에 백업
- 비밀번호·alias 를 비밀번호 관리자에 저장
- **git 에 커밋하지 말 것** (`.gitignore` 에 `*.jks` 확인)

## 3. 출시용 빌드(AAB) 만들기

Play 스토어는 APK 가 아니라 **AAB(Android App Bundle)** 를 받습니다.

먼저 버전을 올립니다. `android/app/build.gradle`:

```gradle
versionCode 1        // 업로드할 때마다 반드시 +1 (되돌릴 수 없음)
versionName "1.0.0"  // 사용자에게 보이는 버전
```

`src/lib/appVersion.ts` 의 `APP_VERSION` 도 같은 값으로 맞춰 주세요.

그다음:

```powershell
cd C:\Users\ddoro\Desktop\suki\my-knitting-log-main\my-knitting-log-main
npm run build
npx cap sync android
```

Android Studio 에서 **Build → Generate Signed App Bundle / APK → Android App Bundle**
→ 2단계에서 만든 keystore 선택 → **release** 선택 → Finish

결과물:

```
android\app\release\app-release.aab
```

## 5. Play Console 에서 앱 만들기

1. Play Console → **앱 만들기**
2. 앱 이름, 언어(한국어), **앱**(게임 아님), **무료** 선택
3. 좌측 메뉴를 위에서부터 채웁니다:

### 앱 콘텐츠 (전부 필수)

- **개인정보처리방침** — 배포된 `/privacy` URL 입력
- **앱 액세스 권한** — 로그인 없이도 대부분 기능 사용 가능하다고 설명.
  심사자용 테스트 계정을 요구하면 구글 계정 하나를 알려 주면 됩니다
- **광고** — 없음
- **콘텐츠 등급** — 설문 작성 (전체 이용가 나옵니다)
- **타겟층** — 만 13세 이상 권장 (아동 대상 아님)
- **데이터 보안** — 아래 6단계 참고. **가장 까다로운 항목**
- **정부 앱** — 아니오

### 데이터 보안 작성 요령

수집한다고 표시할 항목:

| 데이터 | 수집 | 목적 | 필수 여부 |
| --- | --- | --- | --- |
| 이메일 주소 | 예 (로그인 시) | 계정 관리 | 선택 |
| 이름 | 예 (로그인 시) | 계정 관리 | 선택 |
| 사진 | **아니오** | 기기에만 저장, 전송 안 함 | — |
| 앱 활동/기록 | 예 (로그인 시) | 앱 기능(백업) | 선택 |
| 오류 로그 | 예 (신고 시) | 오류 진단 | 선택 |

- **전송 중 암호화**: 예 (HTTPS)
- **데이터 삭제 요청 가능**: 예 → 설정 → 계정 삭제 경로 설명

> 사진은 기기 밖으로 나가지 않으므로 '수집'에 해당하지 않습니다.
> 나중에 사진 클라우드 백업을 켜면 **반드시 이 항목을 갱신**해야 합니다.

## 6. 테스트 → 출시

바로 정식 출시하지 말고 단계를 밟는 것을 권합니다.

1. **내부 테스트** — 최대 100명, 심사 없이 즉시. 이메일로 테스터 등록
2. **비공개 테스트** — 정식 출시 전 필수 단계인 경우가 있음
3. **프로덕션** — 정식 출시

각 단계에서 AAB 를 업로드하고 출시 노트를 적습니다.

> 개인 개발자 계정으로 새로 만든 앱은 **비공개 테스트를 일정 기간(최소 14일)
> 최소 12명 이상과 진행**해야 프로덕션 출시가 열리는 정책이 적용될 수 있습니다.
> Play Console 이 요구하면 뜨개 커뮤니티에서 테스터를 모으는 편이 빠릅니다.

## 7. 출시 후

- **versionCode 는 되돌릴 수 없습니다.** 올릴 때마다 +1
- 심사 반려 사유는 Play Console 알림에 상세히 나옵니다
- 사용자 리뷰에 답글을 달 수 있습니다
- 크래시는 **Android Vitals** 에서 자동 수집됩니다 (앱 내 버그 신고와 별개)

## 체크리스트

출시 버튼을 누르기 전에:

- [ ] keystore 를 두 곳 이상에 백업했다
- [ ] `versionCode` / `versionName` / `APP_VERSION` 이 서로 맞는다
- [ ] Firestore 보안 규칙이 적용되어 있다 (`docs/firestore-rules.md`)
- [ ] 정책·약관 페이지에 빨간 TODO 배지가 없다
- [ ] 실기기에서 Google 로그인이 성공한다 (release 키의 SHA-1 도 Firebase 에 등록했는가?)
- [ ] 계정 삭제가 실제로 동작한다
- [ ] `docs/release-checklist.md` 의 Critical 항목을 통과했다

> **release 키 SHA-1 등록을 잊기 쉽습니다.** debug 키로는 로그인이 되는데
> 스토어에 올린 앱에서는 안 되는 사고가 여기서 납니다.
> Play Console → 설정 → 앱 서명 에서 **앱 서명 키 인증서의 SHA-1** 을 복사해
> Firebase 에도 추가하세요.
